# Project notes

A presentation deck driven by typed content. React + Vite + **TypeScript**, Framer Motion for transitions. The cover's art is the **thinking-orbs** `connecting` orb, drawn by `src/components/CoverOrb/CoverOrb.tsx`: the package's React component ships only 64px and 20px presets, so the deck paints the same animation through its `thinking-orbs/engine` subpath at the cover's own size. It replaced the hand-written R3F dot sphere — three / React Three Fiber are still in `package.json`, but nothing imports them any more.

## Content

- All decks live in **`content/`** as TypeScript modules (one file = one deck; `meta` + a `parts` array, `export default` + `satisfies Deck`). Keep versions here as separate files.
- A deck is **nested**: `parts` hold `slides`. A slide belongs to the part whose `slides` array it is written in — nothing infers it from the nearest `divider` any more, so a reorder cannot move a slide between parts by accident. A part has `id`, `label`, and `slides`; its number is its opening `divider`'s `number`, asked for once (`partNumber()` in `src/lib/parts.ts` reads it back). A part with no divider — `intro`, `closing`, a bonus section — shows its label alone, and `slides: []` is a named slot that renders nothing until it is written. `standalone` on a slide now only suppresses the corner reference; it no longer decides membership.
- Every slide takes both a **`title`** and a **`chapter`**, and they are two jobs. The title is the stage line — a sentence, read off a projector, carrying the one accent word. The `chapter` is the slide's name: short, plain, and what the Contents outline and the studio's state labels print. `chapter` is **required**, so a slide with no name in the outline is a typecheck error rather than a row you cannot navigate by.
- `src/lib/parts.ts` flattens a deck to the linear run it is presented as (`items`, plus `partAt[i]` for the part slide `i` sits in). `decks.ts` does it once per deck and `scripts/lab-states.ts` calls the same function, so the studio's labels and the deck's own chrome cannot disagree.
- **`content/types.ts` is the contract.** Every archetype is a member of the `SlideItem` union, discriminated on `type`, so a misspelled archetype, a `tone` that is not a tone or a `table` with three columns is a compile error while the deck is being written — not a wrong slide on stage. `npm run typecheck` is the gate, and `npm run build` runs it first.
- The **presented** deck is `DEFAULT_DECK` in `src/lib/deck-ids.ts` — currently `version_1`. The app shows that deck and only that deck: a published presentation is one deck, and a way to switch mid-talk is a way to open the wrong one on stage. Change what is presented by changing that constant.
- **All** decks in `content/` are visible in designlab through the screen's `deck` param, so a draft can be reviewed without being presentable.
- A **production build carries only the presented deck**: the glob over `content/` is dev-only, so a draft's copy is never readable in the published JS. The studio runs the dev server, which is why every deck shows up there. One consequence — `export_prototype` is a production build, so an exported prototype has only the presented deck.
- `content/sample.ts` is the **reference** deck (`meta.mark: "Sample Deck"`), one slide of every archetype — plus a second slide for a variant that changes the card itself, `process` written twice, once per `mark`. A second slide of a type it already has becomes its own `Slide` component variant, so writing the variant into `content/sample.ts` is what adds the state; no list in `scripts/lab-states.ts` has to be kept in step with it. It is what a new deck gets started from and what the schema is documented against — never overwrite it to change what is presented.
- The designlab states pin item **ids** from the active deck, so after changing content run **`npm run lab:states`**. Skipping it breaks nothing loudly: the deck falls back to the first slide and every capture becomes a picture of the cover. `npm run lab:states -- --check` exits 1 when they are stale.
- Author a new deck with the **`/new-deck`** command (see `.claude/commands/new-deck.md`): it maps your content onto the existing slide types, writes a new deck module into `content/`, points the import at it, and — with your OK — can add a new slide type when the content needs one.
- Prose fields take **inline Markdown**: `` `code` ``, `*emphasis*`, `[text](href)`, and `**word**`, which renders in the accent color rather than bold — that is the deck's one-accent-word rule. Block Markdown is deliberately not supported; headings and lists are what the archetypes are. `src/lib/text.tsx` owns the parser (`renderInline` to render, `stripMarks` for the plain string).

## Slide types

Thirteen archetypes, each a layout in `src/slides/Slides.tsx` (styles in `src/slides/slides.css`): `cover`, `divider`, `keypoints`, `callouts`, `twocolumn`, `process`, `cards`, `codeui`, `commands`, `promptrun`, `table`, `quote`, `showcase`. `promptrun` is one prompt beside what each model returned for it: three columns, the prompt on the left with a copy button, a result per model after it. The prompt text is **not** in the deck module — `prompt.source` names a file in `content/prompts/`, which `src/lib/prompts.ts` bundles with `?raw`, so the pane, the clipboard and the file cannot drift apart, and editing a prompt is editing the `.md`. A result is a still plus an `href`: the returned page is a whole landing page, too small to read on a slide, so the thumbnail is the exhibit and the link opens the real thing from `public/results/`. `commands` is the reference of calls — one console block per command, laid out in a column each: the call in mono on a dark pane with a prompt chevron, what it `writes` under it, then the line that says what it is for, and `rules` below the row for what holds across the whole set. Paper ground with the panes dark on it, because the slide is a page about commands rather than a terminal. Four calls or more switches it to a three-column reference sheet one step down in size — the count decides that, the way it decides `cards` density, so nothing authors it. An optional `image` puts a capture of what the calls open beside them, and the `src` rule is `showcase`'s — a `public/` path with no leading slash, alt text in a dashed frame when there is no file yet. Every console carries a `CopyButton` unless the item sets `copy: false` — the call is meant to be taken away rather than transcribed off a projector. `split` sets the proportion between the two, the same three steps `divider` and `keypoints` take: unset is `golden-flip` (the capture wide), `golden` turns it round when the calls are the point and the picture only proves the screen exists. It is a designlab param on the deck screen as well. It is what `codeui` and `keypoints` were both being bent into: `codeui` is a document beside an explanation of it, and a set of calls has no document; `keypoints` is a claim beside prose, and a row whose subject is a command and whose object is a file is columns, not a sentence. A `process` step takes an optional `subtitle` — the step restated in the title's own words, set under its name on the same band, not as a first point; and a `process` title runs to 26ch rather than the 15ch default, because the flow under it is the full width of the stage. `mark` (`chip` / `block`) decides how big the step's mark is drawn: `chip`, the default, is the small numbered square a flow gets out of the way; `block` is a tile the height of the card's band with the mark set large in it, for a flow whose marks are the takeaway — `R` · `E` · `D` on the closing slide. Like `marker` and `split` it is both an authorable field and a designlab param on the deck screen. `cards` is the un-ordered sibling of `process`: parallel specimen cards, no numerals, no connectors. Its title and subtitle sit on the same dark band `process` gives its step cards, so the claim separates from what supports it by more than two greys. A card is generic — `title`, optional `subtitle`, and content that is either `points` or `text`, never both — and the item's `quoted` flag decides whether the element wraps every title in quotation marks (for prompts and replies) or leaves them plain (for filenames and names). `callouts` is the evidenced sibling of `keypoints`: the same numbered list, beside one screenshot pinned with the same numbers, so each row has something to point at. A point with no `pin` keeps its number and marks nothing, which is how a failing that a still cannot show still gets said. `showcase` and `callouts` are the ones that render a real image; its `src` is a `public/`-relative path with no leading slash, and an image with no `src` draws its alt text as a visible placeholder. A `cover` takes an optional **`qr`** — `src` (a `public/` path with no leading slash, `showcase`'s rule), `alt`, and an optional `label` and `href`. The slide draws a mark, not the code: a QR at icon size is a decoration nobody can scan, so the cover shows a drawn QR glyph with its label, and a tap opens the real file in the lightbox at the size a room can read. Ground (light/dark) defaults per type in `slideTheme()`; override with an item `theme`.

## Structure

- `src/deck/DeckView.tsx` — deck shell: index state, keyboard/touch nav, header/footer chrome, slide transitions, Contents overlay.
- `src/components/Lightbox/Lightbox.tsx` — every picture in the deck opens full size when clicked, and that is the default rather than a per-slide flag; `lightbox: false` on an image is the opt-out. The overlay's state lives in `DeckView` because the deck's own key handler has to stand down while it is open, and a `showcase` or `promptrun` image's `href` rides along inside the overlay instead of competing with the click. In a designlab component variant there is no deck around the slide, so the picture is a plain `img`.
- `src/components/Contents/Contents.tsx` — the floating Contents overlay with two tabs: **Outline** (two levels, part over chapter — a table of contents to navigate by, not the deck retold) and **Slides** (PowerPoint-style thumbnail grid). Search reads the whole slide, including points the outline no longer shows, so a phrase you remember still finds its slide. Open with the ≡ button or the `O` / `Esc` key.
- `src/slides/Slides.tsx` — the ten slide components + a dispatcher and outline helpers. A `divider` with no `list` (or an empty one) renders solo: same φ : 1 grid, bigger title. `marker` (`number` / `bullet` / `none`) and `split` (`golden` / `even` / `golden-flip`, the golden ratio and its two deviations) are taken by **both** `divider` and `keypoints` — the two archetypes are the same shape, a claim beside a list — and each is an authorable field and a designlab param on the deck screen, so a proportion can be tried before it is written in. Unset is `golden` on a `divider` and `even` on a `keypoints`, which is what each looked like before the fields existed; a divider's row padding also scales with the row count.
- `src/design/` — tokens (light + dark themes, terracotta accent), base, and self-hosted Geist / Geist Mono fonts.
- `src/lib/deck-ids.ts` — `DEFAULT_DECK` and `REFERENCE_DECK`, free of Vite so `scripts/lab-states.ts` can import them in Node rather than parsing them out of the source.
- `scripts/lab-states.ts` — runs under `tsx` and **imports** the decks, so the generator and the app read the same modules through the same contract.

## Conventions

- Prose fields take **inline Markdown**: `` `code` ``, `*emphasis*`, `[text](href)`, and `**word**`, which renders in the accent color rather than bold — that is the deck's one-accent-word rule. Block Markdown is deliberately not supported; headings and lists are what the archetypes are. `src/lib/text.tsx` owns the parser (`renderInline` to render, `stripMarks` for the plain string).
- Keep the accent to the one word / active mark per slide; grounds are warm paper (light) and near-black (dark), never pure white/black.

## Voice — the version_1 presentation style

`content/version_1.ts` is written in one voice, and a slide added or edited there has to be indistinguishable from the ones already in it. The rules, read off the finished deck:

- **Title** — a full sentence ending in a period, not a headline fragment ("Why most of the initial prompts **fail**."). The one `**accent**` is the payload noun or verb and lands at or near the end; never an adjective. When the point is the reader's own ownership the accent goes on *you* ("How **you** run the loop."), and a second accent is allowed only for a filename or command. Imperatives and direct address are the default mood ("Do not reinvent the **wheel**.", "Keep these open in a **tab**."); questions are rare. A `commands` slide prefixes its mode in caps ("**COMP-LED**: …"). Parenthetical self-marking of opinion belongs to the voice — "(for now)", "(highly opinionated)".
- **Chapter** — a plain short noun phrase, two to five words, no period, no Markdown, no accent. A numbered sequence uses the middot: "1 · Landing page prompt example".
- **Kicker** — only on a part's closing takeaway, all caps with an em dash: `PART 3 — TAKEAWAY`. The closing slide's is `THE RED FRAMEWORK`.
- **Note** — one to three sentences of plain prose, never a list. It carries the thesis, the caveat or the scope limit — the thing the rows are not allowed to say. It is where the honesty lives ("As of September 2026, and none of them was in Parts 1–4.").
- **Points and list rows** — teasers, one line at display size; a row that wraps on stage is too long. The dominant shape is `Term — gloss`, and rows within one set stay parallel: all glosses, or all sentences, never mixed. Every row stands alone and never points at another slide.
- **Cards** — `title` is the artifact (a filename, a command, a repo, or the quoted prompt itself with `quoted: true`), `subtitle` is its job in two to five words. A tool card's points run in a fixed order: the exact invoke line in backticks, what it does in one line, then attribution · date · link. A pair of cards names both sides — no option is sold without its price.
- **Links and dates** — link text is the bare domain or `org/repo`, never a raw URL and never "click here". Every third-party tool and reference carries a month-year date, so the audience can see what is still moving. ` · ` separates sources and attribution throughout.
- **Person and tone** — second person for the reader, first person singular for the author's own practice, first person plural only in the bridges. No exclamation marks, no emoji, no hype adjectives; the deck obeys the anti-slop rules it teaches.
- **The recurring move** — negate, then correct: "What the model needs is not more words. It is fewer choices." Once or twice per part.
- **Shape of a part** — `divider` (claim plus three or four bridge rows) → evidence slides → **one** `keypoints` takeaway carrying the `PART N — TAKEAWAY` kicker. Intro, closing and bonus have no takeaway.
- A **divider** has its own rules on top of these: the `note` states the thesis in plain prose, each list row is a claim plus its consequence and stands alone, and no row refers to another slide or names a tool that belongs to Part 4.
